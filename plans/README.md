## Why this set of plans

A live run against a real Electron app (2026-09-02) hit four runtime bugs in sequence that none of
the 391 unit tests caught. The root cause is structural: mutation paths are tested as pure policy
enums with injected closures, no recorded real-app AX trees exist, and the live smoke accepts
`verifier_ambiguous` as a pass. Phase 0 below closes that gap first; everything after it is then
verifiable against real trees instead of hand-built ones.

## Findings considered and rejected / deferred (so nobody re-audits them)

- **PERF-04 warm OCR worker**: measured warm OCR today is 220–330 ms end-to-end including process spawn; the isolation boundary is a recorded design decision (`docs/plans/2026-08-27-bcu-runtime-excellence-design.md`). Not worth the HIGH risk now; revisit if `performance.ocrMs` p50 exceeds 500 ms after plan 023.
- **DEBT-03 shared read-act-read pipeline seam**: HIGH risk of erasing route-specific timing; defer until 025 (outcome policy) and 004 (orchestration tests) land, then re-evaluate with characterization coverage in place.
- **DEBT-04 decompose 19 >150-line functions**: do it opportunistically inside 006/007/008/009/023, not as a standalone refactor.
- **DEBT-08 global runtime actor**: not worth doing — cursor is already `@MainActor`-owned, per-window executor is deliberate, locks sit at synchronous callback boundaries.
- **DEBT-09 rename `AXPipelineV2`**: not worth doing — versioned contract vocabulary used by fixtures/tests; no V3 exists.
- **DEP-02 notarized/versioned release channel**: needs a Developer ID identity and Apple credentials — operator decision, not an executor task. When decided: hardened runtime + timestamp + notarize + staple + versioned asset + checksum required by `install-runtime.sh`.
- **DIR-01 locked-use qualification on a disposable host**: the only remaining item in `openspec/changes/add-bcu-locked-use/tasks.md`; it is a manual, destructive gate (`docs/locked-use-recovery.md`) — must never run on a primary workstation. Not a plan; a checklist already exists in `docs/plans/2026-08-27-bcu-macos-product-parity-design.md:193-200`.
- **DIR-03 first-class task sessions** and **DIR-06 `quit_app` route**: product direction with contract impact; write a design doc (openspec proposal) before any plan. Evidence: three distinct session mechanisms (`X-Background-Computer-Use-Session` header, `launch_app.sessionID` body, `"default"` fallback in Router); launch/quit asymmetry with `run_script` blocked under Control.
- **TEST-09 locked-use E2E**: same as DIR-01.
- **Layering violations**: none found (Actions → StatePipeline/Cursor direction intact; Contracts is a leaf).
- **Prompt-injection content in repo**: none found.
- **`swift-testing` pinned snapshot**: keep; test-only, documented in `openspec/project.md`.
